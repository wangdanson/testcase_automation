# 📈 ODM 報表計算與活動追蹤邏輯 (Report & Tracking)

> **本文件用途**: 記錄 ODM 系統中關於成效報表 API、追蹤碼生成機制、活動狀態遷移、批次更新與營運操作門禁的技術邏輯。

---

## 🧭 零、 操作入口、角色權限與生命週期 (Manual Alignment)
> 📍 來源規格：[ODM 使用者操作手冊](../user_manual/ODM/ODM_USER_MANUAL.md)

### 1. 核心模組入口
*   **活動生命週期**: 廣告活動需依序完成「建立廣告主 → 建立廣告活動 → 建立投放項目 → 綁定素材 → 提交審核 → 上線執行 → 報表追蹤 → 活動結案」。
*   **追蹤與排程入口**: 排 Cue 系統、活動追蹤、上刊通報、活動進度是 ODM 營運追蹤的主要頁面，測試案例需確認資料可從 Cue/活動/投放項目一路追蹤到報表。
*   **報表入口**: 活動成效報表位於活動詳情頁；投放報表位於投放項目詳情頁或活動投放列表；DSP 報表與受眾報告屬於活動/投放詳情的延伸報表。

### 2. 角色與權限門禁
*   **ERP 權限來源**: ODM 登入時會從 ERP 取得角色與權限，測試角色異動時不可只驗證 ODM 本地 UI，需確認 ERP 權限同步後的功能可見性。
*   **CIS 成員門禁**: 活動執行進度僅限 CIS 成員存取，非 CIS 使用者應看到權限不足提示。
*   **SuperDSP 審查門禁**: SuperDSP 素材審查僅限管理員存取，需驗證非管理員無法進入審查頁或操作審核動作。
*   **動作資源模型**: 權限採 `動作:資源` 格式，如 `create:campaign`、`update:placement`、`manage:pack`，測試案例需區分新增、檢視、列表、編輯、刪除與管理權限。

## 📊 一、 報表 API 與數據指標 (Reporting)
> 📍 來源規格：[[ODM] 報表API分析](../source_files/[ODM]%20報表API分析)、[[ODM] CTV 投放成效報告](../source_files/[ODM]%20CTV%20投放成效報告%20調整，基於%20Household%20ID%20(HHID))

### 1. AII (Attention Impact Index) 注意力衝擊指標
*   **定義**: 用於衡量廣告格式的注意力效果，綜合注意力時間、廣告格式特性與標準格式基準。
*   **計算公式**: `AII = (aspect_ratio × duration × default_vcpm) / (std_duration × std_vcpm)`。
*   **事件欄位**: 注意力事件包含 `aclick`、`aclose`、`leave_ad`、`ascroll`；需同時驗證對應的 duration 與 count 欄位。
*   **資料範圍**: 僅納入已上線 (`after_oncue`) 且 ad format 具有 `aspect_ratio` 與 `default_vcpm` 的 Placements。
*   **標準格式**: AII 標準格式 ID 為 `137`，API 查詢需同時帶入實際格式與標準格式，避免缺少基準值導致計算失真。
*   **API 結構**: AII 事件資料透過 API Gateway 依 Placement IDs、Ad Format Type IDs 與 Campaign 走期查詢。

### 2. CTV 與 Household ID (HHID)
*   **核心維度**: CTV-pre-roll 以 Household ID 而非單一設備或 OneID 作為數據聚合基準。
*   **技術定義**: HHID 是家戶 CTV 裝置 ID，OneDATA 內部以 hashID 表示，來源可由 IP 與 user agent 推導。
*   **標籤歸戶**: 年齡性別與興趣標籤會透過 IP 作為 key，比對 CTV 裝置外的家庭成員標籤後歸戶至 HHID。
*   **多標籤分攤**: CTV-pre-roll 可能一個查詢對應多個年齡性別組合，受眾報告需將數值平均權重分配至各年齡性別，避免報表錯亂。
*   **Unique 指標**: CTV 裝置情境下 Unique User 需改為 Unique HHID，且 Unique User / Unique HHID 原邏輯為走期結束後才會出現。

### 3. 報表類型與匯出規則
*   **報表類型**: ODM UI 支援活動成效報表、投放報表、DSP 報表與受眾報告。
*   **活動層級指標**: 活動成效報表需涵蓋總曝光、總點擊、CTR、CPM、CPC、花費、每日數據、每小時數據與媒體報告。
*   **投放層級指標**: 投放報表需涵蓋投放層級曝光、點擊、CTR、日期/小時趨勢、裝置分佈、媒體與版位明細。
*   **DSP 報表**: DSP 日報需涵蓋出價次數、得標次數、得標率與平均出價，並支援時間區間、裝置、地理位置與創意版本等自訂維度。
*   **受眾報告**: 受眾報告需涵蓋性別、年齡、興趣標籤、地理位置與裝置類型。
*   **資料時效**: 使用手冊定義報表數據約每小時更新一次，測試即時性時需避免用分鐘級期待值判定失敗。
*   **Excel 編碼**: 匯出檔案採 UTF-8；若 Excel 顯示亂碼，應以文字匯入並指定 UTF-8。
*   **Sheet 命名**: Excel sheet 名稱需移除特殊字元、超過 31 bytes 時截斷、空名稱預設為 `Tab N`。
*   **數據落差說明**: 第三方平台與 ODM 的曝光認定或計算方式可能不同，驗證時應以 ODM UI 報表作為主要基準，第三方工具作交叉比對。

### 4. ODM 與 SuperDSP 報表計算差異
*   **標準 ODM 計算**: ODM 來源使用一般 `calculate_by_stat` 邏輯，需先確認目標維度資料存在再計算衍生指標。
*   **SuperDSP 特殊計算**: `source = superdsp` 時需套用 `calculate_superdsp_by_stat`，曝光、CTR 與 VTR 計算邏輯不同。
*   **SuperDSP 完整性要求**: SuperDSP 報表需保留所有選定指標欄位，即使沒有資料也要顯示，且需依 SuperDSP 專屬欄位順序排序。
*   **QA 風險**: 產生測試案例時不可用 ODM 標準公式直接驗證 SuperDSP 指標，需依 `superdsp_imp`、`ctr_imp`、`vtr25/50/75/100` 等特殊欄位分別校驗。

## 🏷 二、 活動追蹤、追蹤碼與委刊單匯出 (Campaign Tracking & IO Export)
> 📍 來源規格：[[ODM] 活動追蹤](../source_files/[ODM]%20活動追蹤)、[[ODM] 批次更新走期 ＆ 媒體](../source_files/[ODM]%20批次更新走期%20＆%20媒體)、[第三方媒體平台數據打通](../source_files/[第三方媒體平台數據打通]%20產業鑽石受眾)、[委刊單 Phase 1：新增「總計 (含稅)」](../source_files/委刊單%20Phase%201：新增「總計%20(含稅)」)、[RMN 導入後, 委刊單匯出需求調整](../source_files/RMN%20導入後,%20委刊單匯出需求調整)

### 1. 追蹤碼自動生成機制
*   **自動化流程**: Campaign 建立時可依產業類別自動寫入 Google Ads、Meta、TikTok、DV360 等平台追蹤碼。
*   **多平台數量**: 單一主/子類別需對應四平台追蹤碼；多子類別情境需依子類別倍數生成追蹤碼組合。
*   **事件命名**: 追蹤事件需依平台與產業分類正確命名，產業鑽石受眾情境需避免 Google/Meta/TikTok/DV360 互相混用。
*   **檢視限制**: Campaign 建立後的追蹤碼可供查看，測試案例需確認系統不允許錯誤修改自動生成結果。
*   **跨系統設定**: 第三方媒體平台數據打通需同時驗證 ODM Campaign 自動帶碼、OSS 追蹤碼管理與 OSS 廣告分類「事件名稱」欄位，避免只測 ODM UI 而漏掉來源設定。
*   **角色視角**: AOE 建立 Campaign 時依產業主次類別自動帶入追蹤碼；Data PM 需可檢視追蹤碼管理內容，測試案例需區分操作角色。
*   **CCT Code 對照**: Google Ads、Meta、TikTok 等平台的 CCT code CSV 為追蹤碼資料來源之一，需驗證平台、產業分類與事件名稱的對照正確性。
*   **狀態遷移**: 追蹤碼資料具備「封存」與「解除封存」機制。
*   **資料一致性**: 當委刊單被新增廣告預算或更新走期時，必須同步觸發活動追蹤資料的更新。

### 2. Cue 表與活動追蹤資料生成
*   **Cue 轉換流程**: Cue 表是活動建立前的規劃文件，轉換後會關聯至新活動，但投放項目仍需在活動中另行建立。
*   **委刊單觸發點**: Cue 表狀態達到「已出委刊」或委刊單被匯出時，系統需建立活動追蹤資料。
*   **資料粒度**: Cue 表中每一筆廣告預算應產生一筆對應的活動追蹤資料。
*   **新增預算**: 已匯出的委刊單新增廣告預算時，需新增對應活動追蹤資料。
*   **手動提醒**: 手動新增的提醒類型資料不需連動 Cue 表或 ODM 活動資料，但需可被清楚辨識為提醒用資料。
*   **不可自動覆寫**: Cue 表或 ODM Placement 後續更新，不應直接覆寫活動追蹤中已可編輯的欄位，避免人工追蹤資訊被覆蓋。

### 3. 活動追蹤狀態與灰階顯示規則
*   **委刊狀態**: 使用手冊列出委刊狀態包含「待發送」、「已發送」、「已回簽」、「需修改」，列表需支援狀態更新與備註歷史。
*   **封存委刊單**: 封存某筆 Cue 時，隸屬此委刊單的所有活動追蹤資料需顯示為淺灰底。
*   **移除產品線**: 移除某產品線時，該產品線底下的活動追蹤資料需顯示為淺灰底。
*   **移除廣告預算**: 移除某筆廣告預算時，該廣告預算對應的活動追蹤資料需顯示為淺灰底。
*   **解除封存**: 若資料曾因移除而反灰，解除封存後仍應維持反灰；若未被移除，解除封存後需恢復正常顯示。
*   **篩選條件**: 活動追蹤需支援產品線、走期開始日期區間、負責業務、活動名稱、委刊狀態等條件過濾。

### 4. 第三方追蹤碼批次雙向設定
*   **Campaign 層級設定**: CIS 可在 Campaign 層建立完整追蹤碼清單，並設定每條追蹤碼在哪些 Placements 啟用或停用。
*   **Placement 層級設定**: CIS 可在 Placement 層啟用或停用追蹤碼，儲存後 Campaign 層需看到一致結果。
*   **列表欄位**: 批次設定列表需顯示 Placement ID、Name、格式、狀態、啟用/停用。
*   **過濾器**: 需支援 Name 搜尋、格式、狀態、啟用/停用篩選。
*   **一致性測試**: 測試需覆蓋 Campaign → Placement 與 Placement → Campaign 的雙向同步。

### 5. 委刊單含稅金額與專案製作費
*   **欄位命名**: 委刊單表格需將 `total_budget（未稅）` 改為「總計（未稅）」，並在下方新增「總計（含稅）」。
*   **含稅公式**: `總計（含稅） = 總計（未稅） × 1.05`，需四捨五入至整數；整列背景需維持橘色提示。
*   **總價欄位**: 委刊單中的「總價（未稅）」需改名為「總價」，避免客戶誤解未稅與含稅金額。
*   **專案製作費**: 排 Cue 顯示名稱為「專案製作費(未稅)」，委刊單中需移至「總計（未稅）」上方。
*   **製作費計算**: 專案製作費金額大於 0 且非贈送時，刊登內容需呈現製作金額、營業稅與合計；營業稅為專案製作費 × 0.05 並四捨五入至整數。
*   **贈送情境**: 勾選贈送時，刊登內容的製作金額、營業稅、合計皆為 0，且「贈送素材製作費(未稅)」不可加總至「總計（未稅）」。

### 6. RMN 導入後的 Cue 表與委刊單匯出
*   **接單公司切換**: 輸出 Cue 表與匯出委刊單時，需依接單公司切換 LOGO、檔名、Header、乙方 Email、聯絡人資訊與文件備註。
*   **MAXI 身份輸出**: 以 MAXI 果然行銷身份輸出時，檔名需由「果實夥伴 OneAD CUE/委刊單」改為「果然行銷 MAIX CUE/委刊單」，Header 需改為「MAXI 果然行銷股份有限公司」。
*   **Email 字串輸出**: MAXI 匯出文件中的乙方 Email 需輸出為 `kerina@maxi.com.tw`，但不可更動 User 原本帳號資料。
*   **媒體格式連結**: ERP「操作型媒體格式設定」需新增「媒體格式連結」，RMN 媒體需可設定雲端文件 URL；輸出 Cue 表或委刊單時點擊欄位內容需開啟指定 URL。
*   **RMN 產品顯示**: 僅 RMN 產品需將欄位內容由「RMN」改為 `RMN_媒體平台(合約)名稱`；非 RMN 產品不可被此規則影響。
*   **計價單位顯示**: CPD 顯示天數、CPT 顯示趟數，且欄位資料格式需設為字串；CPD/CPT 以外的計價單位以數值格式呈現。
*   **多產品組合**: OneAD、RMN、操作型媒體可單獨或複數組合輸出，測試需覆蓋 OneAD + RMN、RMN + 操作型、OneAD + 操作型 + RMN 等混合情境。

## 🧩 三、 批次更新、頻次與投放門禁 (Batch Operations)
> 📍 來源規格：[[ODM] 批次更新走期 ＆ 媒體](../source_files/[ODM]%20批次更新走期%20＆%20媒體)、[[ODM] 最高觀看頻次設定調整](../source_files/[ODM]%20最高觀看頻次設定調整)、[[ODM] 投放 id 與頻次設定調整](../source_files/[ODM]%20投放%20id%20與頻次設定調整，以達到跨裝置控制頻次)

### 1. 批次更新支援項目
*   **支援範圍**: 策略、Pacing、優先度、走期、頻次、時段、目標族群、裝置、媒體、Brand Safety、IAS。
*   **失敗處理**: 批次更新需回傳結果摘要並列出失敗的 Placement 與原因，常見原因包含狀態不允許修改、設定值超出範圍、權限不足。
*   **裝置比例**: 裝置批次更新需驗證 IR/MIR 等裝置預算比例總和為 100%。

### 2. 走期批次更新規則
*   **停刊/結案**: Placement 狀態為停刊或結案時，開始日期與結束日期皆不可更新。
*   **非上刊狀態**: 非上刊狀態可更新開始日期與結束日期，但需先模擬更新後平均次數不可小於 0。
*   **上刊狀態**: 上刊狀態只能更新結束日期，開始日期不可更新。
*   **回傳粒度**: 批次走期更新需逐筆 Placement 回傳成功或失敗結果，不能只回傳整批成功。

### 3. 媒體批次新增與移除
*   **新增媒體**: 新增媒體前需確認媒體的 ad format type 具有合法合約，否則該 Placement/媒體組合需回傳失敗原因。
*   **移除媒體**: 未開啟 pacing 時，移除後至少需保留一個媒體；已開啟 pacing 時，移除後至少需保留可承接便宜流量的媒體。
*   **編輯紀錄**: 若勾選的 Placement 為上刊或暫停狀態，批次媒體更新成功後需新增編輯紀錄。

### 4. 頻次控制規則
*   **跨裝置頻次**: 投放 ID 與頻次設定需支援跨裝置控制頻次，避免桌機、手機、CTV 分別計算造成超頻。
*   **Campaign Level**: Campaign level 頻次預設為無限制；若同時設定 Campaign level 與 Placement level，需從嚴認定，例如 Campaign level 1 次、Placement level 2 次時，以 1 次為準。
*   **上刊後編輯**: Placement 上刊後，Speed 與 Publisher Speed 皆可更改頻次設定。
*   **Targeting 類型**: Contextual targeting 與 Sequential signal targeting 屬於投放環境而非投放受眾，不應因 Targeting 類型不同導致頻次鎖定條件不一致。

## 📽 四、 影音流量與內容卡控
> 📍 來源規格：[[ODM] Video 流量管控](../source_files/ODM%20Video%20上傳%20Bitrate%20卡控%20&%20m3u8%20切片導入%20(流量管控))、[TextDrive 倒數計時](../source_files/TextDrive%20新增倒數計時機制)

### 1. 流量管控 (Traffic Control)
*   **Bitrate 卡控**: ODM Video 上傳時，系統會自動檢查並限制 Bitrate 碼率，以確保投放流暢度。
*   **警告標準**: 通用影片 bitrate 超過 2000 Kbit/s、CTV 超過 7000 Kbit/s、凱擘 CTV 超過 3000 Kbit/s 時需提示警告。
*   **阻擋標準**: 影片 bitrate 超過 10000 Kbit/s 或音訊 bitrate 超過 128 Kbit/s 時需阻擋上傳。
*   **KBRO CTV**: 凱擘 CTV 影片 fps 必須為 29.97，不符合時需阻擋上傳。
*   **訊息互斥**: 警告訊息與卡控阻擋訊息不可同時出現，需依嚴重程度只顯示其一。
*   **影片資訊**: 上傳後需顯示影片大小、bitrate、fps、音訊 bitrate 等資訊，供營運判斷素材品質。
*   **切片技術**: 所有影片類型上傳時都需進行 m3u8 切片，並同時輸出 m3u8 與 ts 檔案，優化影音載入速度與流量成本。
*   **使用手冊限制**: 使用者手冊定義影片支援 MP4/MOV，建議 H.264 編碼，檔案大小上限 500MB；測試需覆蓋格式與大小限制。

### 2. 倒數計時機制 (TextDrive)
*   **互動邏輯**: TextDrive 廣告格式中新增「倒數計時」機制，提升點擊衝擊力。

## 🔍 五、 數據驗證門禁 (Data Validation)
> 📍 來源規格：[[ODM] 廣告活動投放條件建立流程簡化(SudoPlacement_)](../source_files/[ODM]%20廣告活動投放條件建立流程簡化(SudoPlacement_))、[segment target v2](../source_files/segment%20target%20v2)、[素材包與素材秒數匹配驗證](../source_files/Untitled%20folder%202025-06-13)

### 1. Placement 欄位檢查
*   **校驗**: 針對 SudoPlacement (2.0 Phase 1) 執行嚴格的前後端資料欄位校驗。
*   **素材秒數匹配**: 驗證「素材包」與「素材秒數」的匹配性，防止不符合版位規範的素材進入投遞隊列。
*   **列表直接更新**: ODM 2.0 Phase 1 支援廣告 Placement 列表直接更新欄位，測試需同時覆蓋前端欄位檢查與後端 API 檢查。
*   **投放狀態門禁**: 投放進行中時部分欄位如預算、Pacing 可調整，但投放類型等基本設定不可變更。
*   **投放啟動條件**: 投放未開始時需檢查走期、投放狀態、素材綁定與活動狀態，避免只看單一欄位判定投放失敗。

### 2. Retargeting Segment Target v2
*   **include/exclude 並存**: ODM Placement 投放類型選擇 Retargeting 時，自訂資料源需可同時設定包含與排除資料源。
*   **互斥選項**: 同一資料源被加入「包含」後，不應再出現在「排除」清單；反向亦同。
*   **必選提示**: 包含與排除皆未選取時需顯示「請至少選擇一筆資料源」；任一側有選取時需移除警示。
*   **數量顯示**: 包含或排除資料源被選取時，按鈕需正確顯示各自的選取數量。
*   **預估量體**: 「預估量體 跨裝置UU」需依包含資料源累計，不應把排除資料源加進估算。
*   **Sequence v2 結構**: 需新增 `segment_targeting_v2`，包含 `enable`、`pool`、`allow`、`deny`，並與既有 `segment_targeting` v1 相容並存。
*   **v1 相容規則**: 當 include 與 exclude 兩者都設定時，v1 `segment_ids` 只列出包含 (`allow`) 的部分，避免舊序列讀到排除資料源。
*   **空設定結構**: 未設定 Retargeting 時，v2 `enable = false`、`pool = 0`、`allow = []`、`deny = []`；v1 也需保持關閉狀態。

### 3. 素材包與素材秒數匹配驗證
*   **資料來源**: 透過 Placement API 的 `inventory.flv_second` 取得使用者在基本資料中選擇的素材秒數；透過 Packs API 的 `videos[0].duration` 取得素材包實際秒數。
*   **驗證時機**: 使用者在素材選擇階段選擇素材包時立即驗證，不匹配時阻止選擇並顯示警告。
*   **秒數區間**: 秒數範圍包含 `1-5`、`6-15`、`16-30`、`31-60`、`61-90`、`91-120`，素材實際秒數需落在選定範圍內。
*   **邊界值**: 15 秒素材匹配 `6-15`，但不匹配 `16-30`；30 秒素材匹配 `16-30`，31 秒素材需落入 `31-60`。
*   **小數處理**: 素材秒數若有小數點，驗證邏輯需先處理小數點秒數後再判斷區間。
*   **錯誤提示**: 警告視窗標題為「素材包與素材秒數不匹配」，需顯示素材包名稱、素材秒數、不匹配原因與建議操作。
*   **操作建議**: 系統需提供修改素材秒數範圍或重新選擇素材包的引導，避免成本錯配造成長秒數媒體誤投短秒素材。
*   **API 錯誤**: Placement API 或 Packs API 失敗時需有 404、403、500、網路錯誤等明確訊息，不可讓使用者在未知狀態下完成錯誤綁定。

## ✅ 六、 SuperDSP 素材審查與跨系統回歸
> 📍 來源規格：[ODM 使用者操作手冊](../user_manual/ODM/ODM_USER_MANUAL.md)、[SuperDSP Pilot for AOE Phase 2](../source_files/SuperDSP%20Pilot%20for%20AOE%20(Phase%202))

### 1. 審查頁狀態與操作
*   **預設頁籤**: SuperDSP 審查頁預設進入 Reviewing 頁籤，需列出待審素材。
*   **Pass 流程**: 通過素材時需選擇產業類別與子類別後 Confirm，素材移至 Passed 頁籤。
*   **Reject 流程**: 拒絕素材時需填寫 Reject Reason 後 Confirm Reject，素材移至 Rejected 頁籤。
*   **退回重審**: Passed 素材可透過 Back to Reviewing 回到 Reviewing 狀態。
*   **拒絕轉通過**: Rejected 素材可重新 Pass，並需重新設定產業類別與子類別。
*   **審核歷史**: 素材詳情需保留審核歷史，包含審核內容、建立者與時間。

### 2. AOE/Partners 回歸關聯
*   **免審核特權**: SuperDSP Partners / AOE 特定代理商素材可能具備自動通過機制；ODM 審查測試需同時覆蓋正向自動通過與一般代理商反向隔離。
*   **產業類別差異**: 人工 Pass 需選擇產業類別；自動通過流程不得錯誤要求在素材層級補填 OneAD 產業類別。
*   **狀態一致性**: 素材在 Reviewing、Passed、Rejected 間切換後，SuperDSP 端素材可選取性與 ODM 審核列表狀態需一致。
