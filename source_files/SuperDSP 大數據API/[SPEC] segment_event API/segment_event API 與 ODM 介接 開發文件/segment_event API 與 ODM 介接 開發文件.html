Segment filter plaid 邏輯

並非所有 placement 皆被設定有 Segment,
所以當使用 campaign_id 執行 SQL 語法時, 僅會得到有 segment 數據的 placement 資料.

舉例說明 :
campaign_id: 1000 底下有三條 placement_id: 5001, 5002, 5003 ,
但僅有 placement_id: 5001, 5002 有被設定 segment 投放

  • 當使用條件 campaign_id: 1000 對 kafka.summing_segment_events 執行 ＳＱＬ 語法,
    僅能取得 5001, 5002 的數值, 5003 將沒有任何數值回傳.

  • 而使用條件 campaign_id: 1000 對 kafka.summing_day_event_dicts 執行 ＳＱＬ 語法,
    則可以取得 5001, 5002, 5003 的數值

  • 基於 權重計算公式：((segment_data / tier_total(segment_data)) * event_data).floor
    若 event_row_data 未作 id 排除的動作, 將會造成數值浮高的狀況出現.

為排除上述狀況產生, 將會先對 kafka.summing_segment_events 先做第一次過濾取得 plaids
後續再拿著 plaids 對 kafka.summing_segment_events 及 kafka.summing_day_event_dicts 做 SQL 撈取

v1/segment_event SQL 語法開發
IP-1675 - 取得議題詳細資料... 狀態

撈取 SQL 兩個資料源

  • Segment： kafka.summing_segment_events

  • Event： kafka.summing_day_event_dicts

並非所有 placement 皆被設定有 segment
所以先拿 @ids 對 kafka.summing_segment_events 做條件撈取
接著收集所有回傳的 @plaids, 即取得"實質有 segment 數據的 plaids"

（ 無論 @tier 是哪個 level , 最後都會以 “plaid“ 的欄位作為輸出 ）

Filter Plaids SQL 

  SELECT distinct (plaid)
  FROM #{ENV['DB_NAME']}.summing_segment_events
  WHERE #{@tier} in ( #{@ids.join(',')} )
  AND day_local between '#{@start_date}' and '#{@end_date}'
  ORDER BY plaid asc

將 Segment and Event 以 SQL 相同條件 把資料取出 ,
取兩組資料的目的是, 將 Segment 的數值使用 權重計算公式 回推成同 Event 之數值.

（ Segment 撈回的“數值”原則上較 Event 大, 將兩者數值利用 權重計算公式 回推同 Event 之比例 ）

Segment SQL 

  SELECT
    {@tier},
    toString(sg) segment_id,
    sumIf(counts, event='cv') as cv,
    sumIf(counts, event='impression') as impression,
    sumIf(counts, event='videoClick') as videoClick,
    sumIf(counts, event='bannerClick') as bannerClick,
    sumIf(counts, event='tb') as tb,
    sumIf(counts, event='eng') as eng,
    sumIf(counts, event='q0') as q0,
    sumIf(counts, event='q25') as q25,
    sumIf(counts, event='q50') as q50,
    sumIf(counts, event='q75') as q75,
    sumIf(counts, event='q100') as q100,
    sumIf(counts, event='view2s') as view2s,
    sumIf(counts, event='view3s') as view3s,
    sumIf(counts, event='view5s') as view5s,
    sumIf(counts, event='view10s') as view10s,
    sumIf(counts, event='view30s') as view30s
  FROM #{ENV['DB_NAME']}.summing_segment_events
  WHERE plaid in ( #{@plaids} )
  AND day_local between '#{@start_date}' and '#{@end_date}'
  GROUP BY #{@tier}, sg
  ORDER BY #{@tier} asc, sg asc

Event SQL 

  SELECT
    #{@tier},
    sumIf(counts, event='cv') AS cv,
    sumIf(counts, event='impression') AS impression,
    sumIf(counts, event='videoClick') AS videoClick,
    sumIf(counts, event='bannerClick') AS bannerClick,
    sumIf(counts, event='tb') as tb,
    sumIf(counts, event='eng') as eng,
    sumIf(counts, event='q0') as q0,
    sumIf(counts, event='q25') as q25,
    sumIf(counts, event='q50') as q50,
    sumIf(counts, event='q75') as q75,
    sumIf(counts, event='q100') as q100,
    sumIf(counts, event='view2s') AS view2s,
    sumIf(counts, event='view3s') AS view3s,
    sumIf(counts, event='view5s') AS view5s,
    sumIf(counts, event='view10s') as view10s,
    sumIf(counts, event='view30s') AS view30s
  FROM #{ENV['DB_NAME']}.summing_day_event_dicts
  WHERE plaid in ( #{@plaids} )
  AND (day_local < '2022-11-08' or exclude = 0 )
  AND day_local between '#{@start_date}' and '#{@end_date}'
  GROUP BY #{@tier}
  ORDER BY #{@tier} asc".squish

將整理後的數據執行 權重計算公式

IP-1719 - 取得議題詳細資料... 狀態

將上述整理之數據, 利用 event 做共同 key 做邏輯運算

  1. 執行 權重計算公式：((segment_data / tier_total(segment_data)) * event_data).floor

  2. 加入排查邏輯, 各 event 若為 0 則直接補 0 不計算 權重計算公式 避免出現無限值

    ( 故資料格式將維持如下, 僅 event 數值有更新異動 )

計算 差異值 並
補回 差異值
IP-1729 - 取得議題詳細資料... 狀態

因 權重計算公式 採無條件捨去, 所以需要補回差值.
將各 event 差異值計算公式： event_data[:event] - tier_total(regressed_segment_data)[:event]

把所有的 event 計算完成, 將計算後的數值更新於 sorted_event_by_tier_id
( 故資料格式將維持如下, 僅 event 數值有更新異動, 各 event 之數值即為 差異值 ) 

{
  cv: 4
  impression: 3
  ...
}

找出 sorted_segment_by_tier_id 該 tier 中全部 Segment 各 event 最小值 . 將 差異值 補回該 event,

補充：若 event 有多筆相等之最小值, 則依據 segment_id 排序, 將 差異值 補在排序最先的 segment_id 之 event
