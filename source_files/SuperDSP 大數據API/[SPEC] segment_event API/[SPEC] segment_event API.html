        SELECT  
      plaid,
      toString(sg) segment_id,
      sumIf(counts,event='cv') as cv,
      sumIf(counts,event='impression') as impression,
      sumIf(counts,event='videoClick') as videoClick,
      sumIf(counts,event='bannerClick') as bannerClick,
      sumIf(counts,event='q0') as q0,
      sumIf(counts,event='q25') as q25,
      sumIf(counts,event='q50') as q50,
      sumIf(counts,event='q75') as q75,
      sumIf(counts,event='q100') as q100,
      sumIf(counts,event='view2s') as view2s,
      sumIf(counts,event='view3s') as view3s,
      sumIf(counts,event='view5s') as view5s,
      sumIf(counts,event='view10s') as view10s,
      sumIf(counts,event='view30s') as view30s
    from kafka.summing_segment_events
    WHERE 
      plaid = 57666
      and day_local between '2022-09-29' and '2022-10-26'
    GROUP BY plaid, sg
    ORDER BY plaid, sg

將 group event row data 數值, 依據 segment row data 權重 重新分配

Step1. 權重計算公式 ：
((segment_row_data / sum(segment_row_data)) * group_event_row_data).floor

  1. example: sg_id → 3eef5326-3e4c-11ed-94f2-42010a006ae7

    1. cv 權重計算：
      (( 116,790 / 573,738 ) * 239,456 ).floor = 48,743

    2. segment 依序結算…

Step2. 重新分配：計算差異值並且加回指定 Segment

sum(cv 權重計算) = 48,743 + 35,951 + 49,367 + 52,799 + 52,591 + 1
= 239,452

  1. 因權重計算無條件捨去的原因，需找到 segment 組合中最小的數值, 將差異值加回

    1. 找出 segment 對應項目最小值 [event_value].min

      1. ex : [48743, 35951, 49367, 52799, 52591, 1].min = 1

    2. 差異值計算公式： group_event_row_data[:cv] - sum(cv 權重計算)

      1. ex : 239,456 - 239,452 = 4

    3. 將差異值加到 segment 對應項目最小值

      1. ex : (event_value).min + (group_event_row_data[:cv] - sum(cv 權重計算))
        = 1 + ( 239,456 - 239,452 )
        = 1 + 4
        = 5

    4. 判定最小值 Segment 之邏輯，請參考 下表說明 

{
  segment_A:
    {
      cv: 10
      impression: 10
      ...
    },
  segment_B:
    {
      cv: 10
      impression: 7
      ...
    },
  segment_C:
    {
      cv: 10
      impression: 3
      ...
    }
}

對所有 segment 判斷 cv 最小值,
出現複數結果, 則繼續迴圈,

對所有 segment 判斷 impression 最小值,
出現單一結果, 則停止迴圈,

並回傳結果 segment_C

補充１：event_key 判斷順位將指定依序為
[cv, impression, q0, view2s, view3s, view5s, view30s, q25, q50, q100, bannerclick, videoclick]

補充２：極少情況下, 所有的 event_key 執行完依然無法得到結果, 將依照 (sg_id).sort 取第一筆 segment 作為回傳結果

Step3. 回傳結果

將所有 segment 的權重計算結果依據 id ＆ sg_id & 項目 加總，作為 API response

整體計算邏輯步驟說明

Step 1.

將 group_segment_row_data 整理為以下格式 event: [seg1_value, seg2_value, ...] 

{
  cv: [116790, 86141, 118286, 126508, 126010, 3]
  impression: [79053, 56624, 79705, 86690, 86218, 2]
  ...
}

Step 2.

將 group_event_row_data 整理為以下格式 event: value 

{
  cv: 239456
  impression: 166717
  ...
}

Step 3.

將上述兩步驟之數據, 利用 event 做共同 key 之關聯執行 權重計算公式
並加入排查邏輯, 各 event 的 segment_row_data 若為 0, 則直接補 0 不計算 權重計算公式 , 避免出現無限值
在此步驟將把所有的 event 計算完成, 預期整理為以下格式 

{
  segment_A:
    {
      cv: 48743
      impression: 33942
      ...
    },
  segment_B:
    {
      cv: 35951
      impression: 24312
      ...
    },
  ...
}

Step 4.

將各 event 差異值計算： group_event_row_data[:event] - sum(event 權重計算)
預期整理為以下格式 

{
  cv: 4
  impression: 3
  ...
}

Step 5.

為了讓各 event 差異值, 可集中全部加回在某 segment 身上,
以 Step3. 所得之格式, 跑迴圈判斷該取哪個 segment 做差異質加回, 以下計算範例說明 

{
  segment_A:
    {
      cv: 10
      impression: 10
      ...
    },
  segment_B:
    {
      cv: 10
      impression: 7
      ...
    },
  segment_C:
    {
      cv: 10
      impression: 3
      ...
    }
}

對所有 segment 判斷 cv 最小值,
出現複數結果, 則繼續迴圈,

對所有 segment 判斷 impression 最小值,
出現單一結果, 則停止迴圈,

並回傳結果 segment_C

補充１：event_key 判斷順位將指定依序為
[cv, impression, q0, view2s, view3s, view5s, view30s, q25, q50, q100, bannerclick, videoclick]

補充２：極少情況下, 所有的 event_key 執行完依然無法得到結果, 將依照 (sg_id).sort 取第一筆 segment 作為回傳結果

Step 6.

將各 event 的差異值, 全部加回 Step5. 所得結果之 segment
