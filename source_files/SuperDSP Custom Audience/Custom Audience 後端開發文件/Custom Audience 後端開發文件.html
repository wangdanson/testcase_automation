修改 to_status api 邏輯判斷

ITP-2802 - 取得議題詳細資料... 狀態

Elain Wu

  • old

  • POST api/v1/superdsp/ad_groups/{id}/to_status

  • 狀態判斷時機：

    • 狀態為草稿修改狀態為上刊

    • 狀態為暫停修改狀態為上刊

    • 上刊中的 ad_group 進行更新

    • 每日 05:00 superdsp_ad_group_status (此次開發會新增排程執行時間點: 00:00)

  • 狀態邏輯：

    • 單一受眾包：

      • 只有客製受眾包 & 打包完成 & 全部過期 => 草稿 → 暫停

      • 只有客製受眾包 & 打包完成 & 最少一個未過期 => 草稿 → 上刊中

      • 只有廣告/網站受眾包 & no ready => 草稿 → 審核中

      • 只有廣告/網站受眾包 & 最少一個 ready => 草稿 → 上刊中

    • 多種受眾包：

      • 所有客製受眾包 & 打包完成 & 全部過期 + 任一廣告/網站受眾包 ready
        => 草稿 → 上刊中

      • 任一客製受眾包 & 打包完成 & 未過期 + 所有廣告/網站受眾包 no ready

        => 草稿 → 上刊中

      • 所有客製受眾包 & 打包完成 & 全部過期 + 所有廣告/網站受眾包 no ready

        => 草稿 → 審核中

  • 審核中 優先權高於 暫停，需先判斷 素材包 → 廣告/網站受眾包 → 客製受眾包

  • 狀態判斷結果如為 審核中/暫停, 需將原因紀錄在 ad_group notes 裡：

    • 素材審核未通過：review_pack_error

    • 廣告/流量受眾包未通過：review_audience_error

    • 客製受眾包未通過：review_custom_audience_error

  • 12/4 修改 oncue 判斷 改成判斷 include 的受眾包至少要過一包

ITP-2796 - 取得議題詳細資料... 狀態

Elain Wu

3

  • 只要 call refresh_sequence , 就會預產當天跟隔天的 sequence,
    因預產的 sequence 可能包含隔天已過期的受眾包, ad_group status 狀態為 上刊,
    故原本檢查 ad_group status 的排程(每日早上五點), 需要新增在 00 點執行

  • 邏輯同 to_status api 邏輯判斷

ex：

  • (現行) 11/14 晚上 11 點 預產 11/15 Sequence

  • (新增時間點於原 task) 11/15 早上 0 點檢查 ad_group 狀態：檢查上刊中 ad_group & target_segment 狀態 變暫停跟審核中, 原因可寫在 pre_campaign notes)

  • (現行) 11/15 早上 2 點打包 target_segment

  • (現行) 11/15 早上 5 點 檢查ad_group 狀態
