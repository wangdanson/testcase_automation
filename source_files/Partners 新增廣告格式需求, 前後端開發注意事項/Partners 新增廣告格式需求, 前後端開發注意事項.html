目的

當 PAD 有需求要新增 ”廣告格式” 時,
前後端工程師可以藉由此文件, 快速理解需要新增異動的程式碼及工作細節

前端

  1. 確認 /media_ad_format_type_reviews/options 是否有回傳最新的格式

  2. 請 TPM 提供格式圖片

  3. 確認新格式預覽的排版方式確認新格式預覽的排版方式

    1. 如有 PC / mobile 兩種版本，需要手刻兩種預覽

  4. 請 TPM 提供廣告預覽素材

  5. 確認新格式欄位是否有需要增減

後端

  1. 確認資料

    1. 確認 PAD 提供的資料是否完整

      1. 格式細項 ad_format_type id (ad_format_type 可能會是多個, 所以務必確認 id)

      2. price_info 的資訊：

      3. 嵌入碼

      4. 計價單位

      5. DEMO Link：在 OSS 格式審核的 preview 頁使用 ( preview_url_params )

    2. 前端需提供的資訊

      1. image_url

  2. 將取得的資訊新增到 ad_format_type_bundle.rb (使用 ActiveHash 紀錄資料)

  3. embed_code 按照舊有邏輯新增相對應的檔案 ( uid 要修改成變數)

    1. ONEAD_TEXT.pub.uid = "<%= data.uid.to_s %>";

參考PR : https://github.com/onead/erp/pull/4121/files
