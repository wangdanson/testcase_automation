功能概述

ERP RTB 合約管理功能為 PAD 部門提供 RTB 競價模式的合約建立與管理機制。本功能支援浮動價格與固定價格兩種 RTB 合約類型，其中浮動價格合約由 PAD 在 ERP 建立，固定價格合約則由 Partners 系統自動建立。

關鍵特性：

  • 除「底價」外的任何資訊變更都需建立新合約來達到更新目的

  • 系統永遠 執行最新的生效合約計價設定

  • 底價編輯記錄與 OYM 系統即時同步

  • 支援立即生效功能，可將待生效合約提前生效

  • 新舊合約並存時，底價同步更新機制確保資料一致性

  • 媒體成本計算功能支援 SuperDSP 毛利分析

    • Phase 2 媒體端的成本是固定分潤, 不用額外開發邏輯

    • Phase 3 媒體端的成本是浮動分潤, 需要額外開發邏輯

計算邏輯

欄位

說明

媒體成本（未稅）

底價 × 曝光數 × (1 - OneAD分潤%)

扣除分潤後的實際成本

媒體 Margin

毛利金額

媒體 Margin / 應收金額

計算範例

假設條件：

  • 底價：$2.0

  • OneAD 分潤：25%

  • 曝光數：1000

計算結果：

  • 媒體成本 = $2.0 × 1000 × (1 - 0.25) = $1,500

  • 應收金額 = $2,000（假設）

  • 媒體 Margin = $2,000 - $1,500 = $500

  • 媒體 Margin rate = $500 / $2,000 = 25%

ad_format_type 建立/更新通知機制

📍 功能位置

路徑：ERP系統 → PM 管理介面 → ad_format_type 管理

功能說明

為解決各部門間的資訊落差問題，當 PM 建立或更新 ad_format_type 後，系統將自動發送通知信給所有相關部門，確保資訊同步。

通知機制說明

項目

內容

觸發時機

PM 成功建立或更新 ad_format_type

收件部門

PAD、ITO、PM、MTO、AOE

發送方式

內部系統通知信

信件主旨

[系統通知] 新增/更新 ad_format_type：{格式名稱}

通知信內容項目（待確認）

  • 格式名稱（format_type_name）

  • 格式代碼（format_type_code）

  • 格式尺寸（dimensions）

  • 適用版位（applicable_placements）

  • 建立/更新時間（created_at / updated_at）

  • 建立/更新人員（created_by / updated_by）

  • 格式說明（description）

  • ….

預期效益

  1. PAD 部門 ：建立合約時能正確選擇sub_ad_type

  2. ITO 部門 ：及時進行系統相關設定

  3. MTO 部門 ：準備對應的技術支援

  4. AOE 部門 ：了解新格式以利後續操作優化

  5. PM 部門 ：確認資訊已正確傳遞
